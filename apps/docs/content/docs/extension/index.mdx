This guide installs the Crikket extension without the Chrome Web Store.

## Install From a GitHub Release

Tester builds are published as GitHub Releases tagged `extension-vX.Y.Z`, `extension-vX.Y.Z-alpha.N` or `extension-vX.Y.Z-beta.N`. Each release attaches:

- `crikket-extension-<version>-chromium.zip`: unzip it, open `chrome://extensions`, turn on `Developer mode`, click `Load unpacked` and select the unzipped folder.
- `crikket-extension-<version>-firefox.zip`: the Firefox build.

The release notes state the version and channel. To build from source instead, continue below.

### Alpha and beta builds

Each version is built in a `prerelease/vX.Y.Z` branch before it reaches `master`:

- **Alpha** (`extension-vX.Y.Z-alpha.N`): published automatically whenever a change is merged into the version's prerelease branch. Newest and least reviewed.
- **Beta** (`extension-vX.Y.Z-beta.N`): published automatically when the finished version is merged to `master`. The changelog has been reviewed.
- **Stable** (`extension-vX.Y.Z`): tagged by a maintainer.

The latest build is always at the top of the Releases page; no one needs to tag anything for alpha or beta.

### Cutting a release (maintainers)

For a stable release (alpha and beta are automatic), make sure `version` in `apps/extension/package.json` is the version to ship (extension versions are not managed by changesets), then push a matching tag such as `extension-v0.2.0`. The tag must agree with `package.json` or the workflow fails. A tag like `extension-v0.2.0-beta.1` can still be pushed by hand for a one-off prerelease.

Both automatic and tagged releases need the repository variable `EXTENSION_APP_URL` (the deployed web app); the build fails without it.

## Prerequisites

- Chrome or any Chromium-based browser
- `web` and `server` running (local or deployed)
- Dependencies installed in repo root:

```bash
bun install
```

<Steps>
  <Step>

  ### Configure Extension Env

  ```bash
  cp apps/extension/.env.example apps/extension/.env
  ```

  Default value:

  ```bash
  VITE_APP_URL=http://localhost:3001
  ```

  If your app is deployed, replace it with the deployed web app URL. The extension reaches the server through the web app's `/rpc` proxy, the same origin where signing in sets the session cookie.

  </Step>

  <Step>

  ### Build Extension Output

  ```bash
  bun run --filter extension build
  ```

  Output path:

  ```bash
  apps/extension/.output/chrome-mv3
  ```

  </Step>

  <Step>

  ### Load Unpacked in Chrome

  1. Open `chrome://extensions`
  2. Turn on `Developer mode`
  3. Click `Load unpacked`
  4. Select `apps/extension/.output/chrome-mv3`

  </Step>

  <Step>

  ### Verify

  - Extension appears in extensions list
  - Popup opens without errors
  - Recording/capture actions can reach your configured backend

  </Step>
</Steps>

## Update Loop

After extension code changes:

```bash
bun run --filter extension build
```

Then in `chrome://extensions`, click reload on the Crikket extension.

## Full-Page Screenshots

The popup's **Capture Full Page** action captures the whole scrollable page as one image. It scrolls the active tab one viewport at a time, calls `chrome.tabs.captureVisibleTab` for each slice, and stitches the slices on a canvas at the page's device pixel ratio. The result opens in the same crop and annotate stage as **Take Screenshot**, which is unchanged. The page's original scroll position is restored afterwards, including when a capture fails.

It does not use the Chrome DevTools Protocol, so the extension needs no `debugger` permission and Chrome shows no "started debugging this browser" banner.

### Limitations

- **Rate limit.** Chromium allows about two `captureVisibleTab` calls per second. Slices are paced about 600 ms apart and a rate-limit error is retried, so a long page takes a few seconds per screen of height. Keep the popup open until the recorder tab appears.
- **Sticky and fixed elements.** Headers, footers and chat widgets that are fixed or sticky appear in every slice, so they repeat down the stitched image.
- **Lazy-loaded content.** Each slice is taken a short moment after scrolling. Images or sections that load later than that can appear blank or as placeholders.
- **Size cap.** The stitched canvas is limited to 16,384 device pixels per side and 268 million pixels in area. Taller pages are cut off at that limit.
- **Scope.** Only the top-level document's vertical scroll is captured. Content inside nested scroll containers and horizontal overflow beyond the viewport are not stitched.
- **Truncation notice.** When a page is cut off at the size cap, the editor shows a notice that the capture stops partway down the page.
- **Popup must stay open.** The capture runs in the popup, so closing it (or switching windows so it loses focus) mid-capture cancels it and restores the scroll position. Moving the loop into the background service worker is a possible follow-up.
- **Restricted pages.** Browser pages (`chrome://`), the Chrome Web Store and the PDF viewer block scripting, so full-page capture shows an error there. If the tab navigates or closes mid-capture, the capture stops with an error and does not touch the new page.
- **Storage.** Results are tried as PNG, then JPEG at decreasing quality, to stay under the roughly 8 MB budget of `chrome.storage.local`; a result that still does not fit is rejected with an error.
